# 排障

按现象查。每条都写明「为什么会这样」和「怎么确认」，因为「接口返回成功」不等于「页面上真的改对了」——
这类问题不回读校验是查不出来的。

- 更完整的背景见 [使用说明](./USAGE.md)
- 写完侧的校验机制见 [使用说明](./USAGE.md) 里的「豆瓣写入通道」一节

## 现象对照表
| --- | --- |
| 「检查豆瓣读取」失败，提示未登录 | 先在浏览器登录豆瓣，再重试 |
| 提示触发验证码 / 429 | 降低抓取频率，或隔一段时间再跑 |
| 解析出 0 条 | 豆瓣改版了页面结构。跑 `npm run test:parse` 定位，抓一份真实 HTML 替换测试数据里的样本 |
| 写入全部失败 | 看日志里的 `attempts`。多半是 ck 取不到或 Referer 校验，改用「标签页通道」并保持一个豆瓣页面打开 |
| 匹配的条目张冠李戴 | 调高「自动接受阈值」，或在待确认列表里手动指定 |
| 评分来回漂移 | 这是 10 分制 ↔ 5 星制的固有损耗，固定用一侧做权威源，不要双向互相覆盖 |
| **演练跑完，豆瓣上却真多了一条收藏** | 旧版本的 bug：「自动」通道下演练会落到标签页注入，而那条通道是真的把请求发出去。**已修**，并加了回归测试（`npm run test:write` 里「演练：一次 POST 都没发」那几条）。更新到最新版即可 |
| **「在看」同步过去变成了「看过」** | 先别急着怪评分 —— 豆瓣的「在看」本身可以打分，扩展默认也是照原样一起写的。按顺序查：① 去设置页「接口自检」点**「读取收藏表单字段」**，看状态字段到底叫什么（是 `status` 还是 `interest`），读到就会自动记住并用于后续写入；② 执行一次单条同步，看顶部有没有红色「N 条状态校验不符」—— 那是写入后回读豆瓣的真实结果，它会直接告诉你豆瓣那边现在是什么状态；③ 若确实是带着评分才被改写，再去设置页打开「写『在看 / 想看』时不带评分」。早期版本在多处兜底里默认写「看过」（状态取不到就凑一个），那些都已改成**明确报错而不是改写** |
| **同步完提示「状态校验不符」** | 这是写完回读豆瓣发现的实际状态与预期不一致，不是报错。常见原因同上（带评分被升级），或这次写入根本没生效。点开提示里列出的条目，去豆瓣页面看它现在到底是哪个状态 |
| 面板上跳过后按钮又亮成「豆瓣 → Bangumi」 | 早期版本的显示 bug（空数组 `every()` 恒真），数据本身没坏。更新到最新版 |
| 开了分享但广播没出现 | 看演练/执行结果里「分享广播」那一行。若显示"未附上"，说明没能从豆瓣弹窗里读到字段名（多数是没登录豆瓣或该条目不是电影）。此时收藏照样写成功、只是没发广播；用设置页「检查分享字段」查看详情 |
| 自定义换算表配了不生效 | 确认「评分换算」下拉确实选了「自定义」，并且点过保存。演练结果区会列出每条实际换算值，用它核对 |
| **按钮点了没反应**（尤其「执行同步」「批量反查豆瓣」） | 别再停留在 `chrome://extensions` 内嵌的选项方框里操作。**在方框右上角点 ✕ 关掉，改用独立标签页的设置页或弹窗**。原因见下方说明 |

### 为什么「内嵌选项框」里点按钮没反应

设置页如果被嵌在 `chrome://extensions` 的「扩展程序选项」方框里，它**不是托管在自己的标签页中**，
Chrome 会拦掉页面的原生模态框（`confirm` / `alert`）。表现就是按钮点下去毫无反应、也没有任何报错 —— 极难排查。

现在这条路已经堵掉了，三重保障：

1. `manifest.json` 里 `options_ui` 用的是 **`open_in_tab: true`**（注意不是 `open_in_new_tab`，
   那个键名 Chrome 不认识，会静默忽略并回退成「内嵌」）。所以设置页现在开在独立标签页里。
2. 页面内的「打开同步面板 / 设置」改用 `chrome.tabs.create`，不再用相对链接 ——
   相对链接在内嵌方框里会**就地跳转**，把整个面板顶掉。
3. 所有确认框改成**页面内自绘浮层**（`src/ui/lib/dialog.js`），彻底不依赖原生模态框。
   同时加了全局错误兜底：任何未捕获的错误都会弹出提示，不会再「点了没反应」。

> 如果你在设置页点「批量反查豆瓣」或「执行同步」没反应，先确认地址栏里没有 `chrome://extensions/?options=`。
> 有的话说明还在内嵌方框里，关掉重开即可。

## 当前状态的诚实说明

- 扫描、解析、匹配、差异计算、页面跳转、写入通道构造这几段逻辑已经跑过回归测试（498 项全过），用的是模拟的豆瓣页面结构和真实的换算规则。
- **豆瓣的写入接口没有实测**：这条路径需要真实登录态，我这边无法发出带 cookie 的请求验证。你在第一次执行时请**先演练、再单条试水**（比如挑一条无关紧要的条目），确认真的写进去了，再批量跑。
- **「分享到广播」的字段名是运行时读出来的，不是文档里抄的**：豆瓣没公开这个接口，所以扩展会读它自己的收藏弹窗来拿字段名。逻辑有测试覆盖，但**真实字段长什么样要你点一次「接口自检 → 检查分享字段」才算确认**。没读到时会照常写收藏、只是不发广播，不会静默。
- 如果写入失败，日志里会保留每个策略的 HTTP 状态和响应片段，把这些贴出来就能定位是接口路径变了还是被风控拦了。
