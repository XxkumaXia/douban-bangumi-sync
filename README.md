# douban-bangumi-sync

**豆瓣 ↔ Bangumi 观影同步**，Chrome MV3 扩展。

把两个站点的收藏双向打通：**想看 / 在看 / 看过**、**评分**、**短评**、**标签**，每一项都能单独开关。
它不是一次性搬家脚本，而是持续双跑：两边有改动后重新扫描 → 算出差异 → 你勾选方向 → 先演练再执行。

- **Bangumi 侧**走官方 API
- **豆瓣侧**没有公开 API，靠解析个人收藏页 + 模拟网页端接口，因此豆瓣改版会失效（有自检可以看出来）

> 用法、配置细节、排障都在 [docs/USAGE.md](./docs/USAGE.md)。想改代码的看 [CONTRIBUTING.md](./CONTRIBUTING.md)。

## 快速开始

### 1. 安装

```bash
git clone https://github.com/XxkumaXia/douban-bangumi-sync.git
```

然后：打开 `chrome://extensions` → 右上角开「开发者模式」→ 点「加载已解压的扩展程序」→ 选中**仓库根目录**（`manifest.json` 就在这一层）。

需要 **Chrome 116+**（Edge 和其他 Chromium 内核浏览器也可以）。

不想克隆的话，Releases 里有打包好的 zip，解压后同样走上面三步。**注意 Chrome 73 之后不允许双击 crx 安装非商店扩展**，只能走开发者模式加载。

### 2. 配置 Bangumi

1. 先在 **新站**登录：<https://next.bgm.tv/demo/login>
   ⚠️ `next.bgm.tv`（新站）和 `bgm.tv`（旧站）登录态**不通用**，必须在新站再登一次
2. 打开 <https://next.bgm.tv/demo/access-token> 新建令牌，名称随意，**有效期选最长那档**
   —— 个人令牌不带 refresh_token，扩展没法自动续期，选短了纯粹给自己找麻烦
3. **立刻复制令牌字符串**，它只在生成时完整显示一次
4. 扩展图标 → 设置 → 粘贴 → 点「检查授权」，显示用户名即成功

### 3. 配置豆瓣

在浏览器里登录豆瓣（随便打开一个豆瓣页面即可），然后回设置页点「检查豆瓣读取」。
**同步期间建议保持至少一个豆瓣页面开着** —— 详见下面的「隐私与安全」。

### 4. 第一次同步，按这个顺序

```
接口自检  →  扫描两侧  →  自动匹配  →  演练  →  执行
```

**务必先演练**：演练会把每条准备发出的请求完整列出来（含 URL、表单字段、静态检查项），
一条都不真的写。确认无误再执行。

## 能同步什么，不能同步什么

| 能力 | 支持情况 |
| --- | --- |
| 豆瓣 → Bangumi：状态 / 评分 / 短评 / 标签 | 支持（官方 API） |
| Bangumi → 豆瓣：状态 / 评分 / 短评 / 标签 | 支持（网页端接口，见下方风险） |
| 分类：动画 / 三次元 / 图书 / 音乐 / 游戏 | 支持，默认只开动画 + 三次元 |
| 条目自动匹配、人工确认、手动指定 ID | 支持，映射表会缓存 |
| 写入豆瓣时同时同步到豆瓣广播 | 支持，同步面板逐条勾选（默认全不勾） |
| 演练模式 | 支持，结果可复制 / 导出 JSON |

**几条必须知道的限制：**

1. **评分换算必然有损**。Bangumi 是 10 分制、豆瓣是 5 星制，豆瓣 → Bangumi 无损，反过来 9 分和 10 分都会变成 5 星。**建议固定一个站点当权威源**，别来回互相覆盖。设置页提供阶梯 / 线性 / 自定义三种模式。
2. **豆瓣改版会导致解析失效**。设置页有「检查豆瓣读取」自检，能直接看出是登录问题还是选择器失配。
3. **有风控**。短时间大量请求会触发验证码或 429。默认写入间隔 1.2 秒、翻页 0.8 秒，别调太小。
4. **短评同步默认关闭**。短评是个人表达，写错不可逆，确认流程顺了再打开。
5. **豆瓣侧的字段名靠实测**。豆瓣没公开接口文档，状态 / 隐私 / 分享这些字段名是从它自己的收藏弹窗里读出来的，设置页有「读取收藏表单字段」按钮可以随时复核。

## 隐私与安全

这一点值得单独说清楚，因为这个扩展申请了不少权限：

| 权限 | 用途 | 会不会外传 |
| --- | --- | --- |
| `cookies` | 读取豆瓣登录态（ck），写入请求要用它做 CSRF | 不会，只用于构造发往豆瓣的请求 |
| `declarativeNetRequest` | 给发往豆瓣的请求补 Referer / Origin 头 | 不会，规则只针对 douban.com / bgm.tv |
| `storage` | 存 Bangumi 令牌、映射表、扫到的快照 | 不会，只在本机浏览器里 |
| `tabs` / `scripting` | 后台请求被拒时，把请求注入到你已打开的豆瓣页面里发出（兜底写入通道） | 不会，只操作豆瓣自己的页面 |
| `offscreen` | service worker 没有 DOMParser，借它解析 HTML | 不会 |

**所有请求都直接发往豆瓣 / Bangumi 官方域名，不经任何第三方服务器**，代码里没有遥测、没有统计、没有自定义后端。
你可以自己查 `src/adapters/` 下两个适配器，所有网络出口都在那两个文件里。

令牌一般权限谨慎使用：本项目只需要读取/写入你自己的收藏，不需要你的密码，也不需要 Bangumi 的 OAuth 授权流程。

## 参与开发

```bash
npm i -D jsdom       # 只有解析测试需要
npm test             # 全量回归（514 项）
npm run test:write   # 只跑豆瓣写入相关
```

打包给别人安装：

```bash
python tools/pack.py                      # 输出到 F:/douban-bangumi-sync-v<版本号>.zip（可用 --out 指定）
```

它会先自检「manifest 引用的资源 / HTML 的本地 src·href / JS 的相对 import」是否齐全，缺一处就报错不产出 zip，避免分发出去才发现漏文件。

提交改动前请看 [CONTRIBUTING.md](./CONTRIBUTING.md)。简单说：**改了行为就要补测试**，而且必须是能真的失败的那一种。
